3. GAYA ARSITEKTUR SISTEM
--------------------------------------------------------------------------------
Sistem menggunakan pola "Modular Monorepo Microservices":

A. FRONTEND (Flutter di Root):
   - Pola: Feature-First Clean Architecture.
   - State Management: Flutter Riverpod (Notifier & StateNotifierProvider).
   - HTTP Network Layer: Dio Client dengan Interceptor terpusat (KlienApi) 
     dan sealed-class wrapper (HasilApi: ApiSukses, ApiGagal, ApiMemuat).
   - Modul Fitur (lib/fitur/):
     * landing_page/ : Master landing web, navbar atas, hero, drawer keranjang.
     * katalog_bunga/: Model produk/kategori, repositori, kartu produk, detail.
     * keranjang/    : State keranjang belanja pelanggan, mutasi kuantitas.
     * pesanan/      : Checkout, kartu ucapan personal, riwayat status pesanan.
     * autentikasi/  : Sesi JWT, login, register, penyimpanan token aman.
     * admin/        : Panel ringkasan omset dan kontrol alur perakitan pesanan.
     * profil/       : Informasi akun, pengalih peran simulasi (Role Switcher).
   - Bahasa Kode: Seluruh penamaan file, fungsi, dan kelas menggunakan 
     Bahasa Indonesia yang rapi dan konsisten.
   - Platform Target Awal: Web (Desktop & Mobile Browser responsive).

B. BACKEND (PHP Native di backend/):
   - Pola: Pure PHP Native Microservices (tanpa framework Laravel monolitik).
   - ORM Database Wajib: Standalone Eloquent ORM (illuminate/database) 
     melalui Capsule Manager untuk interaksi database MySQL yang aman dan bersih.
   - API Gateway (backend/gerbang_api/):
     * Titik masuk tunggal router RESTful berbasis Bramus Router.
     * Penjaga keamanan CORS lintas platform (PenjagaKeamanan.php).
     * Middleware Stateless JWT (firebase/php-jwt) untuk otentikasi.
   - Mikroservis Independen (backend/layanan/):
     1. layanan_autentikasi : Register, Login, JWT Me, Profil.
     2. layanan_katalog     : Kategori Bunga, Produk Buket, Stok, Filter.
     3. layanan_keranjang   : Sinkronisasi Keranjang Belanja Pelanggan.
     4. layanan_pesanan     : Checkout Pesanan, Kartu Ucapan, Nomor Invoice.
     5. layanan_pembayaran  : Rekening Pembayaran, QRIS, Bukti Bayar.
     6. layanan_admin       : Agregasi Omset, Metrik Toko, Status Alur Bunga.
   - Shared Kernel (backend/layanan_bersama/):
     * BasisData.php (Koneksi Capsule ORM ke MySQL).
     * SkemaBasisData.php (Migrasi 7 tabel terstruktur).
     * BenihAwal.php (Seeder akun admin, pelanggan, kategori, dan buket).
     * TanggapanJson.php (Amplop respon standar sukses/gagal korporat).
   - CLI Toolkit (backend/perintah.php):
     * php perintah.php status  (Cek koneksi & dependensi)
     * php perintah.php migrasi (Eksekusi skema database)
     * php perintah.php benih   (Isi data awal)
     * php perintah.php rute    (Daftar endpoint mikroservis)

4. ATURAN TETAP UNTUK PROMPT-PROMPT BERIKUTNYA
--------------------------------------------------------------------------------
1. Pertahankan Tema Klasik Romantis:
   Semua penambahan widget, layout, maupun warna baru WAJIB merujuk ke 
   konstanta WarnaAplikasi (#6B4435, #FAF7F2, #C59B27, #C87D75, #2D1F1B) dan 
   Google Fonts Playfair Display / Plus Jakarta Sans.
2. Bebas Emoji Kasual:
   JANGAN memasukkan simbol emoji pada judul, tombol, snackbar, ataupun copy text. 
   Gunakan ikon Material Icons resmi bernuansa mewah.
3. Pertahankan Struktur Feature-First & Monorepo:
   - Jangan membuat folder acak. Letakkan fitur baru di lib/fitur/<nama_fitur>/ 
     dengan subfolder data/ dan presentasi/.
   - Jika menambah endpoint backend, buat di backend/layanan/<nama_layanan>/ 
     dan daftarkan di backend/gerbang_api/index.php.
4. Gunakan Bahasa Indonesia Baku untuk Penamaan Kode:
   Tetap gunakan Bahasa Indonesia yang bersih untuk nama file, model, repositori, 
   dan provider.
5. Pertahankan UX Web yang Elegan:
   - Navigasi atas (BilahNavigasiAtas) tetap menjadi navigasi utama web.
   - Alur katalog tetap terbuka untuk umum tanpa memaksakan login di awal.
   - Keranjang belanja tetap menggunakan model slide-over drawer (LaciKeranjangWeb).
6. Integritas Standalone Eloquent ORM:
   Jangan menulis raw SQL query sembarangan; gunakan model Eloquent atau Capsule query 
   builder agar aman dari SQL Injection dan konsisten.
7. Jaga Kualitas Kode:
   Setiap perubahan kode harus dipastikan selalu lolos "flutter analyze" dengan 
   0 error dan 0 warning.
